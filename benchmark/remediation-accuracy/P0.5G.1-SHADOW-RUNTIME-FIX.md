# P0.5G.1 Numeric Shadow Runtime Safety Fix

Status: implementation complete. **Not deployed.** Production flags stay **off**.

## Root cause

Stage 1 `ReviewPipelineService.applyNumericAuthority` awaited `SemanticNumericAuthorityService.apply()` whenever mode ≠ `off`. `shadow` therefore sat on the user-visible review path and would add DeepSeek latency (~15–20s) to every request.

`apply()` also invoked the provider on every review, with no eligible-only pre-filter and no independent shadow cap. Hypothetical `WOULD_AUTHORIZE` / `WOULD_ENTER_EVIDENCE` were not logged as such. JSONL on the process filesystem is not a durable Railway source.

## Mode semantics

| Mode | Invocation | Blocking | Findings |
| --- | --- | --- | --- |
| `off` | none | none | none |
| `shadow` | eligible-only, capped, `scheduleShadow()` fire-and-forget | must not await | none (hypothetical gate only) |
| `on` | eligible-only, `applyAuthoritative()` bounded await | timeout fail-open | possible supplemental RULE Finding |

## Eligibility

Reuses P0.5E.2 `extractAnchors` only. Eligible if any of: Arabic-digit `value`, existing `written_number`, `range`, `explicit_percentage`, measurable `unit`, `explicit_multiplier`, or comparator **and** a quantity signal.

Not a Legal Finding decision. No new phrase lexicon.

**ELIGIBILITY_RECALL_LIMITATION:** existing written-number extractor only covers a small English set (`one and a half`, twenty-X, and `one`–`twelve` when `times` is present). Copy such as “one third less” / “twice as fast” with no digits is **ineligible** this round.

## Cap / timeout / errors

- Independent `AAIRP_SEMANTIC_NUMERIC_SHADOW_MAX_PER_PROCESS` (default 100), not shared with general Semantic Shadow.
- Cap skip logs `shadow_cap_reached`; no provider call.
- Shadow and on both use bounded provider timeout. Shadow timeout → `shadow_timeout` log only.
- Shadow `scheduleShadow` swallows throws; no unhandled rejection into the pipeline.

## Logging

Primary: structured **stdout JSON** (`console.info`) with `event_type=semantic_numeric_shadow` (shadow) or `semantic_numeric_authority` (on). Railway logs remain after restart. No new database. No API keys / reasoning / PII.

## Hypothetical authority

Authority Gate still runs in shadow, then **stops before mutation**:

- `would_authorize_numeric_finding` = gate pass
- `would_be_supplemental` = gate pass and not Rule/Playbook equivalent
- `would_enter_evidence_flow` = would be supplemental and mapping is `EVIDENCE_SUPPLEMENT`
- duplicate → `RULE+SEMANTIC_NUMERIC`, not supplemental
