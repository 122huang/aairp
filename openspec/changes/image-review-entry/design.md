## Context

审查应用已有「单条审查」「批量审查」两个入口。单条以文案 textarea 为主，图片上传为可选附件；后端同一套 `ReviewPipelineService`（规则 → Playbook → Open Risk → Vision → 一致性 → 决策/报告）。长图场景下已补齐 Vision 抽字回灌规则、功效/容量宣称扫描与可读性门禁，但 UX 仍把图当成附属物，审前无法强制核对识别文本。

本设计在 **不复制审查引擎** 的前提下，增加图片优先入口，用两段式流程把「识别 → 人工核对 → 审查」产品化。

## Goals / Non-Goals

**Goals:**

- UI 第三入口「图片审查」，与单条/批量并列。
- 两段式：先识别填入可编辑文本框，人工核对后再提交审查。
- 提交载荷含原图 + 核对后文本；复用现有 pipeline 与门禁。
- 用 `entry_mode` 区分入口，驱动报告文案与后续统计。
- 用 `AAIRP_IMAGE_REVIEW_ENTRY` 开关控制是否展示图片入口，便于回滚。

**Non-Goals:**

- 独立图片微服务或新规则引擎。
- 第一期批量图片审查。
- 重做单条/批量入口（仅文案澄清「附图不替代图片审查」即可）。
- 强制用户使用某一 OCR 供应商（沿用现有 OCR/Vision 能力组合）。

## Decisions

### 1. 入口形态：第三 Tab，而非隐藏在单条高级选项

- **选择**：`ReviewMode = 'single' | 'batch' | 'image'`。
- **理由**：图片作业与写文案作业心智不同；藏在单条里无法解决「空文案框」问题。
- **备选**：单条内「图片模式」开关 — 否决，易与现有传图混淆。

### 2. 两段式交互（识别 → 核对 → 审查）

```
上传图 → [识别文字] → 可编辑「识别文本」框 → [开始审查] → 同一 pipeline
```

- **选择**：显式两步，不允许跳过识别直接审（除非用户手动粘贴足够文本进框；仍建议先识别）。
- **理由**：与「审前核对是否识别准确完整」目标一致。
- **备选**：一点审查自动识别 — 否决，核对步骤易被跳过。

### 3. 抽字来源：OCR + Vision 抽字合并进文本框

- **选择**：第一期合并去重写入同一可编辑框；提交时映射为 `text`（核对稿）+ 保留 `images`；可选同时带 `ocr_text` 原始快照（若实现成本低）。
- **理由**：规则引擎已吃 `text` / `ocrText` / `visionText`；核对稿进 `text` 最直接，高亮与 finding 锚点也落在用户所见文本上。
- **备选**：仅 OCR 或仅 Vision — 长图小字召回不足。

### 4. 后端合约：`entry_mode`，不新开审查 API

- **选择**：现有 demo review 提交增加可选字段 `entry_mode: 'image' | 'single' | 'batch'`（默认 `single` 保持兼容）。
- **识别**：复用 `/demo/ocr/extract`（及现有 smart-extract/Vision 抽字能力）；图片入口 UI 编排调用顺序。
- **理由**：逻辑与文案审查相同，避免双 API 分叉。

### 5. 与单条入口边界

- 单条：文案必填倾向；图可选。
- 图片：图必填；文本框为识别核对稿（可空启动，但提交时空稿 + 不可读图触发可读性门禁 → REVIEW）。
- 单条文案处加一句提示：完整审图请用「图片审查」。

### 6. 可回滚：入口级功能开关

- **选择**：环境变量 / 配置 `AAIRP_IMAGE_REVIEW_ENTRY=off|on`（默认 `off` 或仅内场 `on`；命名以实现为准）。
- **行为**：`off` 时 UI **不展示**「图片审查」Tab；API 仍接受可选 `entry_mode`（兼容），但前端不引导该路径。
- **理由**：不好用时可秒级回滚，无需 revert 整 PR；单条/批量不受影响。
- **备选**：仅靠 Git revert — 保留作底线，但日常用开关更快。

### 7. 报告

- `entry_mode=image` 时报告强调识别/核对文本与图片分支；文案分支可标注「来自识别核对」。
- 可读性门禁 finding 保持现有行为。

## Risks / Trade-offs

- **[识别慢/贵]** 长图 OCR+Vision 耗时 → 识别步骤独立，可展示进度；审查步骤不再重复全量抽字时可缓存本次识别结果。
- **[合并抽字噪声]** OCR 噪点进文本框 → 依赖人工删除；后续可加滤噪（非本期必做）。
- **[用户跳过核对]** 仍可能不改直接审 → 两段式降低误操作；门禁兜底不可读图。
- **[与单条传图行为重叠]** 文档/文案提示划清边界，避免两入口结果预期不一致。

## Migration Plan

1. 仅前端加 Tab + Image 面板；API 字段向后兼容（缺省 `single`）。
2. 默认 `AAIRP_IMAGE_REVIEW_ENTRY=off`（或等价），验证通过后再对目标环境打开。
3. 无需数据迁移；旧 case 无 `entry_mode` 视为 single。
4. 回滚：将开关设为 `off`（隐藏 Tab）即可；必要时再 Git revert PR。

## Open Questions

- 识别结果是否在 UI 上区分 OCR/Vision 来源行（第一期可不做）。
- 多图时文本框是合并一份还是按图分页（第一期建议：主图一张长图 + 可选补充图，文本合并一份）。
- `entry_mode` 是否写入 case 记录供检索（建议写入，实现时确认 case schema）。
